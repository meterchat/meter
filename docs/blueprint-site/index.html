What is Meter?

Meter is a version-controlled thinking environment for builders. It sits between your idea and your code — the strategic layer where you debate architecture, lock decisions, and commit structured blueprints that your AI coding agents consume.

The biggest problem with vibecoding isn't speed. It's direction. Builders jump straight into code, spending weeks on custom auth and billing, only to make wholesale breaking changes when the strategy shifts. Meter exists so you build the right thing first, without the debt.

Core Product Decisions

Product Identity: Git for Thinking
Meter is a version-controlled thinking environment. The core metaphor mirrors Git: you debate (write), lock decisions (stage), and commit blueprints (push). Strategy has branches, commits, and history — just like code.
Tagline: Git for Thinking
"Git for thinking" is the headline. It creates productive confusion — your brain knows what Git does and what thinking is, and the collision creates a hook. The subtitle explains: "Debate AI models. Lock decisions. Commit your blueprint."
Primary Action: Commit
The word "Commit" carries a perfect double meaning: committing to your decisions (psychological finality) and committing files to GitHub (technical action). It sits precisely one step before "Ship" — which is exactly where Meter lives in the workflow.
Commit Interaction Model
In chat, the AI asks "log this decision?" — user confirms — decision stages in the Commit dropdown. The dropdown shows staged decisions + blueprint diff. User reviews, optionally unstages items, writes a commit message, and clicks Commit. Decisions save to Decisions tab, blueprints save to Blueprint tab, push to GitHub if connected.
Commit Lives in Chat Messages
The "Decide" button in chat is renamed to "Commit." Clicking it commits the decision directly from where the thinking happened. No header button needed — the action lives where the clarity is. The header can display committed decisions as a read-only log.
Decision Lifecycle: Open → Locked → Committed
Open decisions are just conversations in chat — they don't appear in the log. The decisions log only contains locked and committed decisions. A decision enters the log when the user explicitly confirms it. It becomes "committed" when pushed via the Commit action.
Pricing: Pay Per Thought
Postpaid, metered billing. No seat licenses, no tiers. The meter ticks up in real-time as AI models think. Users pay only for what they use. The live meter in chat shows per-message cost, resetting each message. The header shows the daily running total.
Slash Commands: /money, /revenue, /users, /code
Four commands, named for what the builder needs to know — not which tool is connected. /money pulls from Mercury (runway, balances). /revenue from Stripe (MRR, churn). /users from PostHog (DAUs, retention). /code from GitHub (repos, PRs). Connector-agnostic naming so underlying tools can change without breaking muscle memory.
Connector Set: GitHub, PostHog, Stripe, Mercury
Four connectors, mapped to the four questions every builder asks before a strategic decision. GitHub is the commit target + code context. PostHog is product context. Stripe is revenue context. Mercury is runway context. Gmail, Vercel, Ramp, and Supabase were cut — they don't directly improve strategic decisions.
Inspector Tab renamed: Commands (not Connectors)
Adding a connector IS gaining a command. They are the same thing, so they get the same name. The inspector tab says Commands. The slash menu says Commands. One concept, one word.
Porkbun Connector: v1 Availability, v2 Purchasing
v1: domain availability checks and pricing displayed in chat. v2: in-chat purchase cards for direct domain registration. This establishes the "purchase card" as a reusable chat UI primitive for future transactional actions.
No Tracks/Branches in v1
Cut entirely. The chat itself is the safe sandbox — debating a crazy idea doesn't break the Blueprint because the Blueprint only changes when you Commit. One workspace = one infinite chat = one Blueprint. Branching is a v2 feature if needed.

UI Architecture

Header

Daily meter box (dropdown shows lifetime total, daily breakdown, model breakdown). Commit button removed from header — commit action lives in chat messages.

Chat

Per-message live meter — starts at $0.00, ticks up during AI response, resets per message. Static receipt bar after response completes showing model, tokens, cost, receipt link. "Commit" button on decision-worthy messages replaces old "Decide" button.

Competitive Position

8090 Software Factory shares the thesis that pre-code decisions matter, but executes top-down with rigid enterprise SDLC modules targeting PM-engineer teams at $200/seat. Meter executes bottom-up: chat-first, single-player, pay-per-thought, outputting directly to GitHub and coding agents. Same problem, opposite philosophies.

Multi-model debate tools (Crucible, Multiple.chat, Council AI) stop at the chat layer. Nobody else combines debate + decision logging + blueprint generation + git-native workflow + metered billing.

Positioning

Meter is git for thinking. It is an AI that lets you think before you code. Get the top AI models to debate your strategy, lock decisions, and commit your blueprints — before writing a line of code.

The largest issue with vibecoding is technical debt. Builders jump straight into coding features, spending weeks creating custom auth, billing, and infrastructure, only to make wholesale breaking changes when they pivot their strategy. Meter exists to ensure you build the right product without burdening yourself with debt.
